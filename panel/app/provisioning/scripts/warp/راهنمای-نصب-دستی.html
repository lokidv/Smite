🌐 نصب دستی WireGuard + خروجی از پروکسی / وارپ

📌 این پروژه چیست؟

این نسخه یک کپیِ جداگانه از نصب‌کنندهٔ WireGuard است که بعد از نصبِ وایرگارد، ترافیک TCPِ کلاینت‌ها را از یک پروکسیِ بالادست خارج می‌کند تا IP خروجیِ کاربر = IP پروکسی شود (نه IP سرور). این «پروکسی» می‌تواند یک پروکسیِ residential/SOCKS/HTTP دلخواه باشد، یا Cloudflare WARP که روی همان سرور نصب می‌شود.

هستهٔ VPN: WireGuard
پنل و API: wvpn روی پورت 4000
مکانیزم خروجی: redsocks + iptables
پورت WARP محلی: 127.0.0.1:40000

🔧 چطور کار می‌کند

  • روی همین سرور یک redsocks (هدایت‌کنندهٔ شفاف) نصب می‌شود.
  • ترافیکِ TCP که از اینترفیس wg0 فوروارد می‌شود، در iptables به redsocks محلی هدایت و از پروکسیِ بالادست خارج می‌شود.
  • برای جلوگیری از دورزدنِ پروکسی توسط QUIC، UDP/443 بسته می‌شود تا مرورگر به TCP برگردد.
  • قوانین در PostUp/PostDown فایلِ wg0.conf درج می‌شوند → پس از ریبوت هم پایدارند.
توجه: این روش برای ترافیکِ TCP (وب/HTTPS) است — دقیقاً همان چیزی که «IP پروکسی را نشان بده» به آن نیاز دارد. DNS از NAT سرور می‌رود ولی اتصالِ واقعی از پروکسی برقرار می‌شود.

🧩 پیش‌نیازها

  • یک سرور Ubuntu یا Debian تازه، با دسترسی root.
  • دسترسی به اینترنت.
  • اگر می‌خواهید از پروکسیِ دلخواه استفاده کنید: IP، پورت، نوع (socks5/http-connect)، یوزر و پسوردِ آن پروکسی.

🚀 گام ۱: نصب پایهٔ WireGuard

پوشهٔ پروژه (wginstaller-proxy) را روی سرور کپی کنید و اجرا کنید:

cd wginstaller-proxy
sudo ./install.sh

این کار WireGuard + پنل و API wvpn (پورت 4000) را نصب می‌کند. برای عوض‌کردن پورت پنل:

sudo WVPN_PORT=4001 ./install.sh
نکته: اگر قبل از اجرای install.sh فایلِ /etc/wvpn-proxy.env را ساخته باشید، نصب‌کننده در پایان خودکار خروجیِ پروکسی را هم راه می‌اندازد. در غیر این صورت، طبق حالت‌های زیر جدا اجرا کنید.

🅰️ حالت الف: خروجی از پروکسی دلخواه

  1. فایل تنظیمات پروکسی را بسازید: 
    sudo tee /etc/wvpn-proxy.env >/dev/null <<'EOF'
PROXY_IP=1.2.3.4
PROXY_PORT=8080
PROXY_TYPE=socks5          # یا http-connect
PROXY_USER=username
PROXY_PASS=password
WG_NIC=wg0
REDSOCKS_LOCAL_PORT=12345
EOF
sudo chmod 600 /etc/wvpn-proxy.env
  2. خروجیِ پروکسی را راه بیندازید: 
    sudo bash wvpn/proxy-egress.sh

یا بدون ساختِ فایل، همه‌چیز را در یک خط بدهید:

sudo PROXY_IP=1.2.3.4 PROXY_PORT=8080 PROXY_TYPE=socks5 \
     PROXY_USER=username PROXY_PASS=password \
     bash wvpn/proxy-egress.sh

اسکریپت در پایان، IP خروجیِ پروکسی را تست و چاپ می‌کند.

🅱️ حالت ب: خروجی از Cloudflare WARP

ابتدا Cloudflare WARP را نصب و در حالت proxy (روی پورت 40000) قرار دهید:

  1. افزودن مخزن و نصب: 
    curl -fsSL https://pkg.cloudflareclient.com/pubkey.gpg | sudo gpg --yes --dearmor -o /usr/share/keyrings/cloudflare-warp-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/cloudflare-warp-archive-keyring.gpg] https://pkg.cloudflareclient.com/ $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/cloudflare-client.list
sudo apt-get update && sudo apt-get install -y cloudflare-warp
  2. ثبت و حالت proxy: 
    sudo warp-cli --accept-tos registration new    # نسخهٔ قدیمی: register
sudo warp-cli --accept-tos mode proxy          # قدیمی: set-mode proxy
sudo warp-cli --accept-tos proxy port 40000    # قدیمی: set-proxy-port 40000
sudo warp-cli --accept-tos connect
  3. حالا پروکسیِ بالادست را همان WARP محلی قرار دهید و خروجی را راه بیندازید: 
    sudo tee /etc/wvpn-proxy.env >/dev/null <<'EOF'
PROXY_IP=127.0.0.1
PROXY_PORT=40000
PROXY_TYPE=socks5
WG_NIC=wg0
REDSOCKS_LOCAL_PORT=12345
EOF
sudo chmod 600 /etc/wvpn-proxy.env
sudo bash wvpn/proxy-egress.sh
تست سریع WARP: قبل از راه‌اندازی خروجی، درستیِ پروکسیِ WARP را چک کنید — باید یک IP کلودفلر بدهد: 
curl --socks5-hostname 127.0.0.1:40000 https://api.ipify.org

🔑 اطلاعات دسترسی

پارامترهای WireGuard و پورت پنل:

cat /etc/wireguard/params        # شامل SERVER_PORT، SERVER_PUB_KEY، WVPN_PORT
cat /etc/wvpn/wvpn.json          # شامل apiKey و adminPath
پنل ادمین: http://IP:4000/<adminPath>/
API Key: از /etc/wvpn/wvpn.json
پورت WireGuard: SERVER_PORT در params
Public Key سرور: SERVER_PUB_KEY در params
فایروال: پورت WireGuard (UDP) و پورت پنل (4000/TCP) را باز کنید.

🔌 مدیریت کاربران با API

روت‌های wvpn با apiKey کار می‌کنند و کلاینت با name (یا publicKey) شناخته می‌شود. خروجیِ create کانفیگِ آمادهٔ WireGuard است.

عملیاتروت
ساخت کاربر (خروجی=کانفیگ wg)/create?apiKey=KEY&name=alice
اطلاعات کاربر/info?apiKey=KEY&name=alice
افزایش حجم/تمدید/update?apiKey=KEY&name=alice&addDataGB=10&extendDays=30
غیرفعال / فعال/disable?...&name=alice · /enable?...&name=alice
حذف/remove?apiKey=KEY&name=alice
لیست / بررسی/list?apiKey=KEY · /check?apiKey=KEY&name=alice
KEY="کلید-از-wvpn.json"
curl -s "http://SERVER_IP:4000/create?apiKey=$KEY&name=alice" -o alice.conf

✅ تأیید خروجی

روی سرور، وضعیت سرویس redsocks:

systemctl status wvpn-redsocks

از داخلِ یک کلاینتِ WireGuardِ متصل، IP خروجی را ببینید — باید IP پروکسی/وارپ باشد، نه IP سرور:

curl https://api.ipify.org

🔁 تغییر پروکسی بعداً

اگر پروکسی خراب شد یا خواستید عوضش کنید: فایل env را ویرایش کنید، خروجی را دوباره اعمال و redsocks را ری‌استارت کنید (پروکسیِ قبلی خودکار جایگزین می‌شود):

sudo nano /etc/wvpn-proxy.env          # مقادیر جدید را بگذارید
sudo bash wvpn/proxy-egress.sh         # بازتولید کانفیگ redsocks + iptables
sudo systemctl restart wvpn-redsocks   # اعمال پروکسیِ جدید

🧹 حذف پروکسی / بازگردانی

برای برداشتن خروجیِ پروکسی و بازگشت به حالت وایرگاردِ ساده:

sudo /usr/local/bin/wvpn-proxy-rules.sh down
sudo systemctl disable --now wvpn-redsocks
# و خطوطِ PostUp/PostDown مربوط به wvpn-proxy-rules را از /etc/wireguard/wg0.conf بردارید

🩺 دستورات مفید و عیب‌یابی

systemctl status wvpn-redsocks           # وضعیت خروجی پروکسی
journalctl -u wvpn-redsocks -n 50        # لاگ redsocks
warp-cli --accept-tos status             # وضعیت Cloudflare WARP (حالت ب)
wg show                                   # وضعیت WireGuard
  • خروجی هنوز IP سرور را نشان می‌دهد؟ مطمئن شوید wvpn-redsocks فعال است و پروکسیِ بالادست واقعاً کار می‌کند (تستِ curl --socks5-hostname ...).
  • پورت/نوع/احرازِ پروکسی را در /etc/wvpn-proxy.env دوباره بررسی کنید؛ residential proxy بدون پورتِ درست کار نمی‌کند.
  • بعد از هر تغییرِ env، حتماً systemctl restart wvpn-redsocks بزنید.
